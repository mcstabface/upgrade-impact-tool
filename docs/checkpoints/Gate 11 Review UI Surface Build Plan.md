## Gate 11 Objective

Gate 11 answers this bounded question:

> Can the stable draft review manifest be exposed in a reviewer-oriented UI surface without introducing mutation paths that bypass Gate 10 controls?

The first implementation slice is a read-only static HTML review surface generated from the Gate 9/Gate 10 artifacts.

Gate 11 does not add UI mutation yet.

## Static Surface Contract

The static review surface must expose:

- review status,
- claim task counts,
- evidence review task counts,
- visual review task counts,
- unresolved gap task counts,
- finalization-disabled state,
- review policy,
- claim review cards,
- claim text,
- evidence IDs,
- source lineage,
- visual-review flags,
- unresolved gap acknowledgement tasks,
- read-only reviewer decision/note fields.

The static surface must not include:

- forms,
- JavaScript fetch mutation,
- onclick handlers,
- contenteditable elements,
- direct mutation endpoints.

## Acceptance Criteria

Gate 11 initial slice is complete when:

1. `python -m app.scripts.run_gate11_kb_review_surface` completes successfully.
2. `kbs/manifests/kb_draft_review_surface.html` exists.
3. Validator passes with `[gate11:validate] OK`.
4. Surface contains at least 15 claim cards.
5. Surface contains at least 10 gap cards.
6. Surface includes finalization-disabled state.
7. Surface includes read-only reviewer fields.
8. Surface contains no mutation-capable fragments.
9. Mutation remains delegated to Gate 10 update commands.

## Non-Goals

Gate 11 does not:

- mutate review state,
- accept or reject claims,
- acknowledge gaps,
- finalize drafts,
- call an LLM,
- add richer draft generation,
- introduce a web framework.
